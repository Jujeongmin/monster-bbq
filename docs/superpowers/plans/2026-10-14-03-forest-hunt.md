# 03 숲 사냥터 완성 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 숲 사냥터를 완성한다. 몬스터 4유형(돌진·겁쟁이·원거리·무리), 부위 드롭, 채집, 가방을 넣고, 서버가 사냥 결과를 검증한다(위조한 사냥 결과는 거부).

**Architecture:** 사냥 한 판은 서버가 준 시드로 정해진다. `shared/hunt/plan.ts`의 `planHunt(seed, zone)`이 몬스터 배치(다시 나타나는 몫까지)·채집 지점·오브젝트를 같은 시드로 만들고, 서버와 클라이언트가 똑같이 계산한다. 클라이언트는 "어떤 배치 ID를 잡았고 어떤 지점을 캤는지"만 보고하고, 서버가 배치에 있는지·한 번씩만인지·걸린 시간이 그럴듯한지·가방 칸을 넘지 않는지 검사한 뒤 드롭을 같은 시드로 계산해 준다. 몬스터 행동은 유형마다 순수 상태 기계(`shared/hunt/*.ts`)다.

**Tech Stack:** TypeScript 5.7, Phaser 3.90, React 18, vitest 3, @agent8/gameserver-node 2.

**Spec:** [docs/superpowers/specs/2026-10-14-monster-bbq-design.md](../specs/2026-10-14-monster-bbq-design.md) (3장 사냥, 7장 서버 판정 흐름, 9장 검증 결과)

## Review Focus

### Task 1: 아이템과 세이브 v2

**Produces:** `ITEMS: Record<ItemId, { kind: "meat" | "forage"; price: number; premiumPrice?: number }>`, `type ItemId`, `itemKey(id, grade?)` → `"boar_belly:premium"` / `"shiitake"`, `SaveData` v2 `{ version: 2; day; gold; items: Record<string, number>; hunt: { id: string; seed: number; zone: "forest"; startedAt: number } | null }`, `readSave`가 v1을 v2로 옮긴다(`meat.premium` → `boar_belly:premium`, `meat.normal` → `boar_belly:normal`).

아이템: `boar_belly`(삼겹살) `boar_neck`(목살) `boar_rib`(갈비) `rabbit_leg`(토끼 다리살) `honeycomb`(벌집꿀) `chicken_thigh`(닭다리살) `chicken_breast`(닭가슴살) — 고기, 등급 있음 / `shiitake`(표고버섯) `wild_garlic`(산마늘) `perilla`(들깻잎) — 채집물, 등급 없음.

테스트: 새 세이브 v2 모양, v1 이전, 깨진 `items`(음수·문자열 값, 모르는 키) 정리, `hunt` 모양 검사(틀리면 null), `itemKey`.

### Task 2: 가방

**Produces:** `bagCount(bag: Record<string, number>): number`, `addToBag(bag, key, slots): { bag; added: boolean }`, `BALANCE.hunt.bagSlots = 12`.

테스트: 개수 합, 칸이 남으면 추가, 가득 차면 추가 안 됨(원본 그대로).

### Task 3: 사냥터 계획

**Produces:** `planHunt(seed: number, zone: "forest"): HuntPlan` — `{ objects: { kind; x; y }[]; spawns: { id: string; monster: MonsterId; x; y; wave: number }[]; nodes: { id: string; item: ItemId; x; y }[] }`. `wave 0`은 처음부터 있고, `wave n`은 다시 나타나는 몫(잡은 만큼 차례로 등장). 숲: 멧돼지 3·뿔토끼 3·독침벌 2·들닭 무리 2(무리당 3마리), 다시 나타나는 몫 2배, 채집 지점 10개.

테스트: 같은 시드 같은 계획, 다른 시드 다른 계획, ID가 전부 다름, 몬스터·지점이 오브젝트 밑동과 시작 지점에 겹치지 않음, 무리는 서로 가까이(반경 40 안).

### Task 4: 드롭

**Produces:** `dropFor(seed: number, spawn: { id: string; monster: MonsterId }): ItemId` — 몬스터 드롭 표의 가중치를 `seed`와 `spawn.id`로 정한 난수로 고른다.

테스트: 같은 입력 같은 결과, 몬스터 표에 있는 아이템만, 1,000번 돌리면 가중치에 가까운 비율.

### Task 5: 몬스터 유형 상태 기계

**Produces:**
- `fleer.ts`(뿔토끼): `wander` → 플레이어가 `fleeRange` 안이면 `flee`(반대 방향으로 빠르게) → 일정 시간 뒤 `rest`(멈춤, 이때 잡기 쉬움) → `wander`. 맞으면 바로 `flee`.
- `shooter.ts`(독침벌): 플레이어와 `keepDistance`를 유지하며 맴돈다 → 사거리 안이면 `aim`(예고, 방향 고정) → `fire`(발사체 1개 생성, `{ pos, dir, speed, life }`) → `cooldown`. 발사체는 `stepShot`으로 움직이고 `shotHits(shot, player, radius)`.
- `pack.ts`(들닭 무리): 평소엔 무리 중심 근처를 배회. 무리 중 하나라도 맞으면 `angry` 상태가 무리 전체에 퍼진다(`angerPack`) → 쫓아가서 가까우면 `peck`(짧은 예고 후 근접 공격, 한 번에 한 번만 맞힘).
- 기존 `charger.ts`(멧돼지)는 그대로.
- 다 같이 쓰는 `isVulnerable`: 멧돼지 `recover`, 토끼 `rest`, 벌 `cooldown`, 닭 `peck` 직후 — 카운터 판정용.

테스트: 유형마다 상태 전이, 한 번만 맞힘, 사냥터 밖으로 안 나감(큰 dt), 무리 분노 전파.

### Task 6: 서버 사냥 검증

**Produces:** `applyAction(save, action, ctx: { now: number; random: () => number })`에 두 행동 추가.
- `{ type: "startHunt", zone: "forest" }` → `save.hunt = { id, seed, zone, startedAt: now }`(진행 중인 사냥이 있으면 덮어씀: 이전 사냥은 버려짐).
- `{ type: "finishHunt", huntId, kills: { spawnId; grade }[], gathered: string[], ko: boolean }` → 검사: `save.hunt?.id === huntId`, `kills`의 `spawnId`가 계획에 있고 중복 없음, 다시 나타나는 몫은 앞선 몫 수만큼만, `gathered`가 계획의 지점이고 중복 없음, `now - startedAt >= kills.length * BALANCE.hunt.minMsPerKill`, 아이템 수 ≤ `bagSlots`, `grade`는 `"premium" | "normal"`. 통과하면 드롭(`dropFor`)과 채집물을 넣고(ko면 각 아이템 절반, 내림), `hunt = null`. 실패하면 `bad_hunt`이고 세이브 그대로(진행 중인 사냥도 그대로).
- `sellAll`은 `ITEMS`의 값으로 판다(고기는 등급별 값).
- `huntResult`(계획 02의 임시 행동)는 없앤다.
- 서버 `act`는 `ctx = { now: Date.now(), random: Math.random }`, `LocalTransport`도 같은 것을 넘긴다.

테스트(vitest + 서버 하네스): 정상 보고 반영, 중복 킬 거부, 모르는 spawnId 거부, 순서를 건너뛴 다시 나타나는 몫 거부, 너무 빠른 보고 거부, 가방 초과 거부, 다른/끝난 huntId 거부, ko면 절반, 거부 후 세이브와 진행 중 사냥 그대로.

### Task 7: 몬스터 그림 자르기

Codex 시트(`rabbit_sheet.png`, `bee_sheet.png`, `chicken_sheet.png`, 4×4)와 다시 그린 걷기(`hunter_walk.png`, `boar_walk.png`, 4×3)를 `slice_characters.py`에 추가해 `art/test/{rabbit,bee,chicken}/…`, 걷기 행 교체. 발 위치 확인. 사용자에게 보여 준다.

### Task 8: 장면 — 계획대로 배치와 유형별 몬스터

장면은 `init({ plan, seed, huntId })`로 계획을 받는다. 오브젝트·채집 지점·처음 몬스터(wave 0)를 계획대로 놓고, 잡을 때마다 다음 wave의 몬스터를 하나씩 등장시킨다. 몬스터마다 유형별 상태 기계를 돌리고 그림 행(걷기/특수 동작)을 고른다. 벌의 독침 발사체, 닭의 쪼기, 토끼의 도망을 연출한다. 기존 멧돼지 손맛(예고 화살표, 카운터 등)은 그대로.

### Task 9: 장면 — 채집, 가방, 보고

채집 지점 근처(24px)에서 PC는 `E`, 모바일은 "줍기" 버튼 → 1초 동안 진행 막대 → 가방에 넣음(가득 차면 `t("hunt.bagFull")`). 잡으면 드롭 아이템이 가방에(가득 차면 바닥에 남지 않고 사라짐 + 알림). HUD는 가방 칸 `n/12`. 끝날 때 `{ huntId, kills, gathered, ko }`를 `hunt:end`로 보낸다(가방 내용이 아니라 보고).

### Task 10: 하루 흐름 연결과 관문

`DayFlow`: 사냥 단계에 들어갈 때 `startHunt` → 받은 `save.hunt`로 `planHunt` → 장면에 넘김. 끝나면 `finishHunt` → 주방. 정산 화면에 아이템별로 판 내역(임시). 관문: 브라우저에서 사냥 → 귀환 → 팔기 → 골드 증가, 새로고침 유지. 개발자 콘솔에서 위조 보고(`LocalTransport.act`로 중복 킬)를 보내면 거부되고 세이브가 그대로.
