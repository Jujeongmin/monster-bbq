# 04 연구 주방과 메뉴 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 저녁 주방을 만든다. 가진 재료 최대 3개 + 조리법 1개로 요리를 시도해 레시피를 발견하고(성공 / 아깝게 실패 힌트 / 완전 실패), 도감에서 찾은 요리와 힌트를 보고, 오늘 팔 메뉴를 고른다. 레시피 정답 표는 서버에만 있고 클라이언트 번들에는 없다.

**Architecture:** 정답 표 `RECIPES`는 `server/src/recipes.ts`에만 둔다. 판정 규칙(`shared/kitchen/cook.ts`)은 순수 함수이고 표를 인자로 받는다. `applyAction`의 `ActionContext`에 `recipes`가 추가되어 서버는 자기 표를, 로컬 모드(개발 빌드)는 `import.meta.env.DEV`로 막은 동적 import로 같은 표를 넘긴다. 운영 빌드에서는 그 import가 통째로 빠지고, 빌드 결과물을 검사하는 스크립트가 관문이다. 결과는 세이브의 `lastCook`에 남아(시도 ID 포함) 응답이 끊겨 다시 보내도 재료를 두 번 쓰지 않는다. 클라이언트가 아는 것은 요리 ID 목록(`shared/content/dishes.ts`), 이름과 도감 힌트 문장(i18n), 그리고 자기가 찾은 레시피(세이브의 `cookbook`)뿐이다.

**Tech Stack:** TypeScript 5.7, React 18, vitest 3, @agent8/gameserver-node 2, Node 24(타입 제거로 `.ts` 스크립트 실행).

**Spec:** [docs/superpowers/specs/2026-10-14-monster-bbq-design.md](../specs/2026-10-14-monster-bbq-design.md) (4장 요리, 7장 서버 판정 흐름 2번, 8장 1차 범위)

### Task 2: 판정 규칙과 행동

**Consumes:** Task 1 전부. **Produces:**
- `judgeCook(items: ItemId[], method: Method, recipes: Record<DishId, Recipe>, cookbook): CookOutcome` — 재료 집합과 조리법이 표의 요리와 같으면 `new`(cookbook에 있으면 `known`). 아니면 표 순서대로 가장 가까운 것을 찾는다. 우선순위: 재료 집합은 같고 조리법만 다름 → `near/method`; 조리법이 같고 재료가 그 요리의 부분집합인데 하나만 모자람 → `near/missing`(모자란 재료의 `taste`); 조리법이 같고 그 요리 재료에 하나만 더 넣음 → `near/extra`; 그 외 → `fail`.
- `hintsFor(itemIds: ItemId[], recipes, cookbook, open: DishId[]): DishId[]` — 이 재료들이 들어가는 요리 중 아직 못 찾은 것의 힌트를 연 목록(기존 + 새것, 중복 없음, `DISHES` 순서).
- `servings(recipe: Recipe, items: Record<string, number>): number` — 재료마다 등급 합친 개수의 최솟값.
- `ActionContext`에 `recipes: Record<DishId, Recipe> | null`.
- 행동 `{ type: "cook"; attemptId: string; items: string[]; method: Method }`: `recipes`가 없으면 `unavailable`. `attemptId`가 `lastCook.attemptId`와 같으면 세이브 그대로 돌려줌(오류 아님). 검사: `attemptId`는 1~40자 문자열, `items`는 아이템 키 1~3개이고 아이템 ID가 서로 다름, 각 키를 1개 이상 가짐, 조리법이 `METHODS`에 있음 → 아니면 `bad_cook`. 통과하면 각 키 1개씩 차감, `judgeCook`, `new`면 cookbook에 추가하고 `hints`에서 뺌, `lastCook = { attemptId, outcome }`.
- 행동 `{ type: "setMenu"; dishes: string[] }`: 전부 cookbook에 있음, 그 조리법이 `tools`에 있음, 중복 없음, 개수 ≤ `BALANCE.kitchen.menuSlots`(2) → 아니면 `bad_menu`. 통과하면 `menu = dishes`.
- `finishHunt`: 얻은 아이템(ko면 절반 후 남은 것)의 ID로 `hintsFor`(recipes가 있을 때만).
- `BALANCE.kitchen = { menuSlots: 2, maxIngredients: 3 }`.

테스트(`shared/kitchen/cook.test.ts`, `shared/actions.test.ts`, 시험용 작은 표를 직접 만들어 씀):
- `judgeCook`: 정답 → new, 찾은 정답 → known, 조리법만 틀림 → method, 하나 모자람 → missing + taste, 하나 더 → extra, 모자람과 더함이 둘 다 맞으면 missing 우선, 엉뚱함 → fail + method.
- `hintsFor`: 관련 요리만, 찾은 요리 제외, 이미 열린 것 유지.
- `servings`: 등급 합산, 재료 하나라도 0이면 0.
- `cook`: 재료 하나씩 차감(성공·실패 모두), new면 cookbook 추가·힌트 제거, 같은 attemptId 재전송은 재료 그대로 같은 결과, recipes 없으면 `unavailable`, 거부(세이브 그대로): 같은 ID 두 등급, 없는 재료, 0개, 4개, 빈 목록, 모르는 조리법, 모르는 키, attemptId 없음.
- `setMenu`: 정상, 거부(세이브 그대로): 못 찾은 요리, 도구 없는 요리, 3개, 중복.
- `finishHunt`: 얻은 재료로 힌트가 열림, ko로 0개가 된 재료는 힌트를 열지 않음.

- [ ] 테스트 먼저 → 실패 확인 → 구현 → `npx vitest run` 전체 통과 → 커밋 `feat(kitchen): cooking judged against the table, menu choice, hints from the haul`

### Task 5: 주방 화면 — 연구

**Consumes:** Task 2·3. **Produces:** `src/screens/kitchen/Kitchen.tsx`(탭: 연구 / 도감 / 메뉴, 맨 아래 "장사 준비" 버튼은 Task 6), `Research.tsx`, `kitchen.css`, i18n 키.
- 냉장고: 가진 아이템 키마다 아이콘(`art/test/items/icon_<id>.png`), 이름(`itemName`), 개수. 누르면 냄비 칸(최대 3)에 들어가고 다시 누르면 빠진다. 같은 아이템 ID는 하나만(다른 등급을 누르면 바꿔 넣음).
- 조리법 다섯 버튼(굽기·끓이기·볶기·튀기기·무치기). 재료 1개 이상 + 조리법이 골라져야 "만들어 보기"가 눌린다.
- 보내기: `{ type: "cook", attemptId: crypto.randomUUID(), items, method }`. 요청 중 버튼 잠금, 실패 시 같은 attemptId로 재시도 버튼. 받은 `lastCook.outcome`을 결과 창으로: new → "새 레시피!" + 요리 이름(작게 튀어 오르는 연출), known → 이름 + "이미 아는 맛", near → 뚜껑이 말풍선(`kitchen.hint.method` / `kitchen.hint.missing.<taste>` / `kitchen.hint.extra`), fail → 망한 요리 이름(`kitchen.fail.<method>`)과 웃긴 한 줄.
- 다 쓴 재료는 냄비 칸에서 빠진다.

임시 뚜껑이 대사(07에서 승인받아 교체):
- method: "재료는 딱 맞아! 불 쓰는 법이 문제야…"
- missing.meat: "향은 좋은데… 씹을 게 하나 빠졌어."
- missing.veg: "고기는 맞는데 뭔가 향긋한 게 하나 더 있어야 할 것 같아…"
- missing.sweet: "짭짤하기만 해. 달콤한 게 하나 있으면 좋겠는데…"
- extra: "거의 다 왔어! 쓸데없이 끼어든 게 하나 있어."

망한 요리: grill "숯검정 덩어리", boil "정체불명 죽", stirfry "냄비에 눌어붙은 무언가", fry "튀김옷만 남은 튀김", season "슬픈 샐러드".

확인: 브라우저에서 사냥 → 주방 → 삼겹살 구이 시도(성공 연출), 같은 시도(이미 아는 맛), 삼겹살 끓이기(조리법 힌트), 엉뚱한 조합(망한 요리). 화면 캡처로 스스로 점검하고 고친다.

- [ ] 컴포넌트 작성 → `npx tsc --noEmit` → 브라우저 확인·수정 → 커밋 `feat(kitchen): research kitchen screen`
