# 06a 골드 성장 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 장사로 번 골드로 사냥 장비, 주방, 가게를 업그레이드하고 실제로 강해진다. 도시락을 챙겨 사냥에서 먹는다.

**Architecture:** 업그레이드 표는 `BALANCE.upgrades`(항목마다 단계별 비용과 효과)에 있고, 세이브는 항목별 단계만 가진다(`upgrades`). 서버 행동 `buyUpgrade`가 골드·다음 단계·잠금 조건을 검사한다. 효과는 순수 함수 `shared/growth.ts`(`huntStats`, `menuSlots`, `bagSlots`, `seatBonus`, `toolQuality`)로 한 곳에서 계산해 서버 검증(가방 칸, 메뉴 슬롯, 손님 수)과 화면(사냥 능력치, 조리 판정 구간)이 같은 값을 쓴다. 도시락은 주방에서 알고 있는 요리를 재료로 싸고(`packLunch`, 서버가 재료 차감), 사냥에서 먹으면 회복·버프(화면 효과), 사냥이 끝나면 도시락은 비워진다.

**Tech Stack:** TypeScript 5.7, React 18, Phaser 3.90, vitest 3.

**Spec:** [성장과 수익화 설계](../specs/2026-10-14-growth-monetization-design.md) 2장(사용자 승인: 06a/06b 나누기, 초안 숫자대로), [전체 설계](../specs/2026-10-14-monster-bbq-design.md) 5장 업그레이드·3장 도시락.

## Global Constraints

- 이전 계획의 제약 전부(서버 판정, `t()`, 정답 표 서버 전용 + `check:bundle`, UI는 키트 A + 갈무리, 그림은 승인 후).
- 숫자는 `BALANCE.upgrades` 한 곳. 화면과 서버가 같은 함수로 효과를 계산한다.
- 보스 재료가 필요한 단계(근접 4단계 등)와 장 진행으로 열리는 도구(웍·튀김기·도마)는 03b 전까지 "잠김"으로 보이고 살 수 없다. 냄비는 골드로 산다(1장 끝 해금은 03b에서 보스 처치로 바꿈).
- 서버 하네스 테스트는 실행 전에 사용자에게 알린다.

## Review Focus

- 골드가 모자라거나, 마지막 단계에서 더 사거나, 잠긴 단계를 사려 하면 거부, 세이브 그대로 → Task 1 테스트.
- 가방 업그레이드 뒤 사냥 보고의 가방 칸 검사가 늘어난 칸으로 계산된다(서버와 화면이 같은 값) → Task 2 테스트.
- 메뉴 슬롯 업그레이드 뒤 `setMenu`가 늘어난 슬롯을 받는다 → Task 2 테스트.
- 도시락 재료가 모자라면 싸지 않는다, 도시락 칸보다 많이 쌀 수 없다 → Task 5 테스트.
- 업그레이드 화면에서 연속 클릭해도 두 번 사지 않는다(요청 중 잠금) → Task 3 확인.

### Task 1: 업그레이드 표와 구매

**Produces:**
- `BALANCE.upgrades: Record<UpgradeId, { costs: number[]; locked?: number[] }>` — `costs[i]`는 단계 i+1 → i+2 비용, `locked`는 03b 전까지 못 사는 단계(목표 단계 번호).
  - melee: [300, 900, 2400], locked [4] / ranged: [400, 1500] / armor: [300, 1000, 2800] / bag: [200, 500, 1000, 2000] / menu: [400, 1200, 3000] / pot: [600] / wok: [1500] locked [2] / fryer: [3000] locked [2] / board: [5000] locked [2] / grillQuality: [500, 2000] / potQuality: [500, 2000] / seats: [800, 1600, 3200, 6400] / lunchbox: [300, 1500].
  - 효과 값: melee 피해 [10, 14, 19, 26], ranged 피해 [5, 8, 12]·사거리 배율 [1, 1.1, 1.1], armor 체력 [100, 130, 170, 220], bag 칸 [12, 15, 18, 21, 24], menu 슬롯 [2, 3, 4, 5], quality 판정 배율 [1, 1.15, 1.3], seats 손님 [0, 1, 2, 3, 4], lunchbox 칸 [1, 2, 3].
- `SaveData.upgrades: Partial<Record<UpgradeId, number>>`(없으면 1단계; 도구 4종은 0 = 없음, 1 = 있음), `readSave` 정리.
- 행동 `{ type: "buyUpgrade"; id: UpgradeId }`: 다음 단계가 없으면 `max_level`, 잠김이면 `locked`, 골드 부족이면 `no_gold`. 통과하면 골드 차감, 단계 +1. 도구(pot/wok/fryer/board)를 사면 `tools`에 조리법 추가(boil/stirfry/fry/season).

테스트: 비용대로 단계 오름·골드 차감, 도구 구매가 `tools`에 반영, 거부 3종(세이브 그대로), 세이브 정리(모르는 ID·음수·범위 밖 단계).

- [ ] 테스트 → 실패 확인 → 구현 → 통과 → 커밋 `feat(growth): upgrades bought with gold`

### Task 2: 효과 계산과 서버 검증 연결

**Produces:** `shared/growth.ts`: `huntStats(save) → { meleeDamage, rangedDamage, rangedRange, maxHp }`, `bagSlots(save)`, `menuSlots(save)`, `seatBonus(save)`, `toolQuality(save, method) → number`, `lunchSlots(save)`. 연결: `finishHunt`의 가방 칸 = `bagSlots(save)`, `setMenu` 상한 = `menuSlots(save)`, `planService` 손님 수 += `seatBonus`(서버와 클라이언트 둘 다 같은 인자로 부름 — `planService(seed, { day, reputation, menu, seats })`).

테스트: 단계별 값, 가방 업그레이드 뒤 13번째 아이템이 들어감, 메뉴 3개 허용, 좌석으로 손님 +1(서버 검증과 같은 계획).

- [ ] 테스트 → 실패 확인 → 구현 → 통과 → 커밋 `feat(growth): upgrade effects in one place, used by the server checks`

### Task 3: 업그레이드 화면

정산 화면에 "업그레이드" 버튼 → 키트 A 패널: 분야(사냥 / 주방 / 가게)별 줄. 줄마다 아이콘(기존 그림: 무기 = 사냥꾼 그림 대신 아이템 아이콘, 도구 = 조리 그림, 좌석 = 불판), 현재 → 다음 효과, 비용, "구매" 버튼(골드 부족·잠김·최대면 비활성 + 이유). 요청 중 잠금. 결과 골드는 하단 바에 바로 반영.

확인: 브라우저에서 골드를 넣고(로컬 세이브) 근접·가방·냄비·메뉴 슬롯 구매, 비활성 이유 표시, 새로고침 유지.

- [ ] 작성 → `npx tsc --noEmit` → 브라우저 확인·수정 → 커밋 `feat(growth): the upgrade screen`

### Task 4: 사냥과 조리에 효과 반영

- 사냥: `HuntScene`이 `huntStats`(근접·원거리 피해, 사거리, 최대 체력)와 `bagSlots`를 쓴다(장면 데이터로 넘김).
- 조리: `CookStage`가 `toolQuality(save, "grill" | "boil")`를 받아 불판의 `burnAt`과 냄비의 `boilOverMs`에 곱한다(판정 구간이 넓어짐). 순수 규칙 함수에 배율 인자를 추가(`stepGrill(g, dt, quality = 1)`, `stepPot(p, dt, quality = 1)`), 테스트 추가.

테스트: 품질 1.3이면 같은 시간에 덜 탐, 넘침이 늦게.

- [ ] 테스트 → 실패 확인 → 구현 → 통과 → 브라우저 확인 → 커밋 `feat(growth): stronger hunts and kinder tools after upgrades`

### Task 5: 도시락

- 세이브 `lunchbox: DishId[]`. 행동 `{ type: "packLunch"; dishes: string[] }`: 찾은 요리만, 칸(`lunchSlots`) 이하, 재료가 있으면(각 요리 레시피의 재료를 보통 등급부터 1개씩) 차감해 담음, 아니면 `bad_lunch`. `finishHunt`가 도시락을 비운다.
- 도시락 효과(`BALANCE.lunch`): 요리 값으로 회복량(값 × 0.8, 최대 체력까지), 꿀 토끼다리구이·닭백숙은 10초 이동 +20%.
- 주방에 "도시락" 탭(키트 A): 찾은 요리 중 칸 수만큼 골라 "도시락 싸기".
- 사냥 HUD: 도시락 아이콘(요리 그림) 버튼, 누르면 먹음(한 번씩).

테스트: 싸기 정상(재료 차감), 거부(못 찾은 요리, 칸 초과, 재료 부족), 사냥 끝나면 비워짐.

- [ ] 테스트 → 실패 확인 → 구현 → 통과 → 브라우저 확인 → 커밋 `feat(growth): lunchboxes for the hunt`
