# 07b 고깃집 개편 2단계 (밤 장사) Implementation Plan

> **For agentic workers:** superpowers:executing-plans (inline). 출시 전이라 큰 검토자 에이전트는 돌리지 않는다(사용자, 2026-10-15). 테스트·타입 검사·실제 화면(1280×720) 확인으로 끝내고 푸시.

**Goal:** 데이브 더 다이버 반쵸 스시의 야간 영업. 긴 불판 카운터 앞에 요괴 손님이 앉아 주문하고, 반달이가 주방에서 자동으로 굽고, 손주가 카운터 뒤 통로를 직접 걸어(WASD/조이스틱) 창구에서 요리를 받아 나른다. 잔일 3종(숯 갈기·불판 갈기·음료 따르기), 말풍선 인내심, 빨리 나르면 팁. 정산 서버 검증 완성, 쟁반·짚신·큰 숯통 업그레이드, 정산 화면.

**Architecture:** 장사 한 판의 규칙(조리 대기열·창구·쟁반·숯·불판·음료 판정·손님 상태)은 Phaser 밖 순수 상태 기계 `src/game/service/shift.ts`(테스트됨). `ServiceScene`은 그 상태를 그리고 입력만 넘긴다. 손님 계획(`shared/service/plan.ts`)에 음료 요청이 더해지고, 정산(`shared/service/settle.ts`)은 손님별 {요리, 기다린 시간, 음료 판정}을 seed·조리 시간·인내심·경과 시간으로 검사해 판매·팁·음료값·평판을 서버가 계산한다. 세이브 버전은 그대로(v7): 새 업그레이드 ID는 없으면 기본 단계, `ServiceSummary.drinks`는 없으면 0으로 읽는다.

**Spec:** [고깃집 운영 개편 설계](../specs/2026-10-15-restaurant-v2-design.md) 2장(2026-10-16 카운터 구조), 4장(밤 장사), 7장(반달이), 9장 2단계, 10장.

## Global Constraints

- **숫자 초안 — 사용자 승인됨 2026-10-16**(팁 기준만 추천대로 완화, 전부 `BALANCE.service`·`BALANCE.upgrades`, 플레이로 조정):
  - 손님: 기본 6명 + 평판 10마다 1명, 6~14명. 간격 4~8초, 인내심 30~45초, 식사 6초. 의자가 다 차면 문 앞에서 줄(인내심은 흐름).
  - 음료 요청(손님마다 seed): 40% 없음, 30% 식사 전 보리차(무료, PERFECT면 팁 ×1.5), 30% 식사 후 사이다 15골드 / 식혜 20골드(PERFECT ×1.5). BAD = 평판 −1.
  - 팁: 주문부터 받기까지 걸린 시간이 인내심의 35% 안이면 요리값의 30%, 60% 안이면 15%, 그 뒤 0. 보리차 PERFECT면 ×1.5(최대 45%).
  - 평판: 만족 +1, 화나서 나감 −2, 음료 BAD −1.
  - 숯: 100%에서 시작, 초당 1.5% 감소(큰 숯통 2·3단계 1.1%·0.8%). 30% 밑이면 조리 시간 ×1.5, 0이면 ×2. Space 한 번에 +15%, 한 번 0.35초 손이 묶임(80% 넘게 채우는 건 시간 손해 — 데이브의 와사비).
  - 불판: 손님이 나간 자리는 더러움, Space 4번(각 0.25초). 더러운 자리엔 손님이 앉지 않고, 깨끗한 자리가 없으면 문 앞에서 기다린다.
  - 음료 따르기: Space를 누르는 동안 1.2초에 잔이 참. 선(70%) ±6% PERFECT, ±15% GOOD, 그 밖·넘침 BAD.
  - 이동: 걷기 110px/초(640 기준), Shift 달리기 ×1.6, 쟁반에 무엇이 있으면 ×0.9. 짚신 1/2/3단계 ×1 / 1.1 / 1.2.
  - 창구는 4접시까지(꽉 차면 주방이 기다림). 쟁반 2/3/4칸(요리·음료 섞어서).
  - 업그레이드 값: 쟁반 2단계 700, 3단계 2,000 / 짚신 2단계 500, 3단계 1,500 / 큰 숯통 2단계 600, 3단계 1,800. 자리 업그레이드(값 그대로)의 뜻이 "손님 +1"에서 **의자 +1(4→8)**로 바뀐다.
- 화면 좌표(640×360, 배경 2배): 카운터 위판 y≈208~222, 앞판 224~268, 바닥 272~326. 손주는 카운터 뒤(발은 앞판에 가림 — 앞판·바닥 띠를 배경에서 잘라 손주 위에 한 번 더 그림). 의자 x 90~470(의자 수만큼 고르게), 음료 수레 x≈440·숯통 x≈475(통로 오른쪽 끝, 주방 앞), 창구 접시 x 510~620. 메뉴 패 6개(배경 x 220~434, y 84~130)에 요리 아이콘 + 남은 그릇 수.
- 그림(전부 사용자 승인 후 `art/`): 배경 승인됨(`art/test/shop/hall.png`). 반달이 8동작 승인됨. 새로 뽑을 것은 작업 1. 방식: Codex 구도 → PixelLab `image_to_pixelart`(faithful, 150)로 도트 변환 → 정수 2배. 후보는 **도트 변환본으로** 보여 준다. PixelLab은 하루 보너스 생성만 남음(2026-10-28 충전) — 시트 하나에 한 번.
- 승인 전 자리 채움: 손님 = 지금 사냥 몬스터(옆걸음), 손주 = 지금 사냥꾼 옆모습, 불판 = 지금 `test/cooking/grill.png`. 코드로 그리지 않는다.
- 사용자에게 보이는 글은 전부 `t()`(ko 기준, en 같은 키). UI는 지금 키트(`ui2`) + 갈무리, CSS 색 박스 금지.
- 서버 행동은 public endpoint. 기다린 시간·음료 판정은 클라이언트 말이라 상한으로 묶는다(조작해도 최대 팁 45%·음료 ×1.5).
- 서버 하네스(`npm run test:server`)는 실행 전에 알린다. 작업마다 커밋, 작업 6 끝에 점검표·푸시.

## Review Focus

- 기다린 시간이 그 요리의 최소 조리 시간보다 짧거나 그 손님 인내심보다 길면 거부. 손님 도착 + 기다린 시간이 실제 경과 시간을 넘으면 거부.
- 음료 판정은 seed가 음료를 요청한 손님에게만, 그 음료로만. 요청 없는 손님의 음료 보고는 거부.
- 같은 보고를 두 번 보내도 골드·평판은 한 번만.
- 쟁반 칸 수는 클라이언트만 지키는 규칙(서버가 알 필요 없음) — 서버는 요리별 개수 ≤ 준비한 그릇만 본다.
- 새로고침해도 장사가 이어진다(지금처럼 sessionStorage: 시계·서빙·마감 + 숯·불판 상태).
