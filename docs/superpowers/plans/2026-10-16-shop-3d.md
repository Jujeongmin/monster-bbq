# 밤 장사 3D 전환 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development 또는 superpowers:executing-plans(사용자가 고른 방식). 출시 전이라 큰 검토자 에이전트는 돌리지 않는다(사용자, 2026-10-15). 작업이 바뀔 때마다 사용자에게 "진행할까요?"(2026-10-16). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 밤 장사 화면을 Phaser 2D에서 Three.js 3D 방(직교 카메라, 도트 그림 2배 정수)으로 바꾼다. 손주는 낮은 카운터 뒤를 걷고, 손님은 앞 의자에 등을 보이며, 카운터 위 화로는 없앤다. 장사 규칙과 서버 보고는 그대로다.

**Architecture:**
- 규칙은 지금 `src/game/service/shift.ts`(`Shift`)를 그대로 쓴다.
- 그 상태를 "무엇을 어디에 그릴지"로 바꾸는 순수 함수 `lookAt`(`src/game/shop3d/look.ts`, 테스트 가능)을 둔다.
- 그 결과를 Three 장면에 그리는 `ShopView`를 둔다.
- 위쪽 막대, 말풍선, 버튼, 터치 조작은 Three 캔버스 위에 겹친 React HUD로 그린다.
- `ServiceGame.tsx`는 WebGL이 되면 3D, 안 되거나 `?shop2d`이면 지금 Phaser 화면을 띄운다.

**Tech Stack:** TypeScript 5.7, React 18, three 0.160.0(신규, 버전 고정), Phaser 3.90(사냥, 2D 대체 화면), vitest 3.

**Spec:** [밤 장사 3D 설계](../specs/2026-10-16-shop-3d-design.md). 시험판: `art-src/mockups/spike3d/index.html`(카메라·조명·좌표 참고, 버리는 코드).

## Global Constraints

- 화면 960×540으로 그리고 정수 배율로 보인다. 직교 카메라, 기울기 0.22rad, 손주 따라가기 ±25단위. 마우스로 카메라를 돌리는 기능은 없다(사용자 2026-10-16).
- 1 월드 단위 = 480폭 그림의 1픽셀 = 화면 2픽셀. 서 있는 그림은 모두 카메라를 정면으로 보고(`rotation.x = -기울기`), 제 픽셀 크기 그대로 쓴다. 텍스처는 Nearest, 밉맵 없음. 위치는 0.5단위로 맞춘다.
- 카운터 위 화로는 없다. 잔반(지저분한 손님)은 카운터 위 접시·흘린 자국으로 보인다. 규칙(40%, 4번 문질러 팁 25, 못 치우면 다음 손님이 화냄)은 그대로다.
- 의자는 3~5개(이미 `BALANCE.growth.seats = [3, 4, 5]`). 앉은 손님 그림에 의자가 그려져 있으니, 손님이 앉은 자리에는 빈 의자를 겹쳐 그리지 않는다.
- 반달이는 주방 배식대 뒤에 서서 허리 아래가 가려진다(잘린 곳이 보이면 안 됨).
- `shift.ts` 규칙과 숫자, 서버 보고 `{ served, left, cleaned }`는 바꾸지 않는다(이름·주석만).
- 사용자에게 보이는 글은 전부 `t()`(지금 `service.*` 키). UI는 지금 키트 그림(`art/test/ui2/*`, `ui-btn` 등)으로 만들고, CSS 색 상자로 새 창·버튼을 만들지 않는다.
- 그림은 승인 전엔 대신 쓰는 그림으로(설계 8장 "그림이 오기 전까지"). 새 그림은 Codex → `art-src/codex/charsnap.py` → 사용자 승인 → `art/`.
- 작업마다 커밋. 마지막 작업에서 `docs/VERSE8.md` 점검표를 돌리고 GitLab `develop`·GitHub `main`에 푸시한다.

## Review Focus

- **창 크기가 정수 배율이 아닐 때**(예: 1366×768, 폰 가로): 픽셀이 뭉개지지 않아야 한다. 작업 2의 `displayScale` 테스트가 정수 배율을 고르고, 1배보다 작을 때만 소수로 줄인다.
- **밤 중간에 새로고침**(`loadShift`로 이어 하기): 잔반·쟁반·배식대가 그대로 다시 보여야 한다. 작업 3 테스트 "되살린 상태도 같은 모습".
- **터치 기기**: 조이스틱과 행동 버튼, 음료는 누르고 있다 떼기. 버튼 밖으로 손가락이 나가도 따르기가 끝나야 한다. 작업 5 테스트 `moveFrom`과 작업 6의 `pointerleave` 처리.
- **WebGL이 없거나 꺼진 기기**: 빈 화면 대신 2D 장사 화면이 떠야 한다. 작업 5 테스트 `canUse3D`.
- **문 앞에 손님이 여럿 몰릴 때**: 걷는 손님이 앉은 손님 앞에, 말풍선이 겹쳐도 읽혀야 한다. 작업 3 테스트 "걷는 손님은 앉은 손님보다 앞(z가 큼)".

### Task 3: 무엇을 그릴지 — `lookAt` (순수 함수, 이 계획의 핵심 테스트)

**Files:**
- Create: `src/game/shop3d/look.ts`, `src/game/shop3d/look.test.ts`

**Interfaces:**
- Consumes: `Shift`, `Guest`, `Target`, `LAYOUT`(shift.ts), `Z`(작업 2)
- Produces:

```ts
export type Pose = "stand" | "walk" | "carry" | "serve" | "scrub" | "grind" | "pour";
export type Glow = { kind: "pass" } | { kind: "drinks" } | { kind: "coal" } | { kind: "seat"; seat: number; mess: boolean } | { kind: "guest"; id: string };
export interface GuestLook { id: string; tex: string; x: number; z: number; flip: boolean; bubble: { icon: string; patience: number; shake: boolean } | null }
export interface SeatLook { x: number; stool: boolean; plate: string | null; mess: boolean }
export interface ShopLook {
  waiter: { x: number; flip: boolean; pose: Pose; carried: string | null };
  guests: GuestLook[]; seats: SeatLook[]; pass: string[];
  bandal: string; coal: number; pour: number | null; glow: Glow | null;
  plates: Record<string, number>; served: number; gold: number; platesLeft: number;
}
export const YOKAI = ["dokkaebi", "gumiho", "reaper", "ghost"] as const;
export function lookAt(shift: Shift, time: number, moveX: number, hold: { poseUntil: number; busy: Pose }): ShopLook
```

텍스처 키는 지금 `ServiceScene`과 같은 이름을 쓴다: `yk_<요괴>_<walk_0|walk_1|sit|eat|happy|angry>`, `dish_<id>`, `prop_cup_tea`, `prop_cup_cider`, `prop_bowl_sikhye`, `prop_plate_dirty`, `bandal_<idle|breathe|grill|turn>`. x는 게임 960폭 좌표 그대로 두고, 월드로 바꾸는 건 `ShopView`가 한다. 규칙은 지금 `ServiceScene.draw`·`drawGuest`·`setPose`·`glowTarget`을 옮긴다. 화로가 없어진 대신 아래가 바뀐다.
- `seats[i].plate`: 그 자리 손님이 `eating`이면 `dish_<그 손님 요리>`, 아니면 `null`.
- `seats[i].mess` = `seat.dirty`.
- `seats[i].stool`: 자리가 비었거나 손님이 아직 걸어오는 중(`walk`)이면 `true`.
- 손님 z: 걷기(`queue`·`walk`·`leaving`)는 `Z.walk`, 앉음은 `Z.seated`.
- 반달이: 요리 중이면 300ms마다 `grill`/`turn`, 아니면 900ms마다 `idle`/`breathe`. 사건 반응(`smile`·`serve`)은 작업 6이 덮어쓴다.
