## 설계 1/3 — 레시피와 데이터 규칙 (승인됨)

- 레시피 표 공개: 서버 전용 `server/src/recipes.ts`를 없애고 `shared/content/recipes.ts` 하나로(재료, 조리법(표시용), 기본 가격, 세트당 그릇 수). 맞히기가 없으니 숨길 이유가 없다. `npm run check:bundle`과 `scripts/check-bundle.ts`도 정리.
- 세이브에 "본 적 있는 재료" 목록(사냥 정산 때 서버가 채움). 도감 실루엣의 재료 아이콘 공개에 씀.
- `research(dish)`: 서버가 필요한 재료를 다 본 적 있는지, 골드가 있는지 확인 → 골드 차감, 요리 열림(레벨 1).
- `upgradeDish(dish)`: 서버가 골드 + 그 요리 재료를 빼고 레벨업 → 가격·세트당 그릇 수 증가(숫자는 밸런스 표, 초안 숫자 승인 필요).
- 메뉴판 `openShop(menu)`: `[{dish, sets}]`, 칸 수 = 기존 메뉴 칸 업그레이드. 서버가 재료를 세트 수만큼 빼고 오늘 밤 준비된 그릇 수를 정함. 남은 그릇은 영업 끝에 버림.
- 특급 재료 세트는 가격이 조금 오름. 일반 재료부터 씀(도시락 규칙과 같음).
- 세이브 v5 마이그레이션: 이미 찾은 레시피 → 레벨 1로 열림. 직접 조리용(`lastCook`, `tools`, 도구 품질 업그레이드) 제거. 대체 업그레이드는 2단계에서 정함.

## 남은 설계 (다음 세션에서 제시)

- **2/3 밤 장사**: 가게 단면도(승인된 shop_bg) + 손주 아바타 탭 이동·서빙 큐, 손님 흐름(요괴 단골 4종, 인내심), 주방 자동 조리(세트 → 그릇, 창구 최대 대기 수), 숯·불판·음료 잔일 규칙, 주문 마감/홀 마감(이미 구현, 유지), 정산 서버 검증 재작성(서빙 수·팁·음료·평판), 도구 품질을 대신할 업그레이드.
- **3/3 화면·연출·영향**: 주방(도감 실루엣/연구/강화/메뉴판) 화면, 연구 성공 연출(데이브 더 다이버식 컷신 — 별도 요청, 컷 구성 후보 승인 필요), 대화창(새 패널 그림 승인 대기), 06a 성장과 06b 수익화 영향, 테스트 전략.
