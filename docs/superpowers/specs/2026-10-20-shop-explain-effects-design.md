# 가게 개편 3단계: 밤 장사 설명과 효과 (설계)

> 상태: **구현됨**(계획 `docs/superpowers/plans/2026-10-20-shop-explain-effects.md`, 2026-10-20). 설계와 다른 점: 팁은 빠르기와 무관해서 서빙 등급(빠름!/좋아/늦었어)은 돈 없는 손님 반응으로만 보인다(기다린 시간 ÷ 인내심 0.4/0.75).

2026-10-20. 가게 개편 순서(2026-10-16 합의) 1 배치 → 2 걸어 다니는 낮 가게 → **3 설명·효과** → 4 장사 중 메뉴 추가 → 5 직원 중 3단계. 사용자가 질문 없이 바로 시작하라고 해서(2026-10-20) 아래 결정은 대부분 **제 판단**이다. 표시한 곳을 읽고 고쳐 주면 된다. 프로토타입이므로 연출은 확정이 아니라 계속 다듬는다(CLAUDE.md).

## 1. 왜

지금 3D 밤 가게는 규칙은 다 돌아가지만 두 가지가 비어 있다.

- **할 일을 알려 주지 않는다.** 첫 밤에 무엇을 해야 하는지(창구에서 요리 받기 → 말풍선 손님에게 주기 → 숯·음료·뒷정리) 어디에도 나오지 않는다. 낮 가게는 가까운 곳에 "E 고르기" 말풍선이 뜨는데 밤 가게에는 없다. 밤 행동 키가 스페이스뿐이라 E를 누르던 사람은 막혔다(오늘 E도 되게 고침).
- **손맛이 약하다.** 서빙·팁·화남·음료 판정이 모두 작은 글자 팝("팁 +6") 하나로 끝난다. 데이브 더 다이버 반쵸 스시는 같은 순간에 동전이 튀어 골드로 날아가고, 손님이 기뻐하고, 소리가 나고, 숫자가 굴러 오른다.

## 2. 목표 / 비목표 / 반목표

- **목표**
  - 처음 하는 사람이 첫 밤 1~2분 안에 창구 → 손님 → 숯·음료·뒷정리를 스스로 해 본다.
  - 가까운 대상마다 "무엇을 할 수 있는지"가 늘 보인다(PC: 키, 모바일: 행동 버튼 글자).
  - 서빙·팁·화남·음료·숯·마감마다 데이브 수준의 눈·귀 반응이 있다.
- **비목표**: 규칙·숫자·서버 정산은 바꾸지 않는다(팁 공식, 인내심, 숯 소모, 음료 배수 그대로). 4단계(장사 중 메뉴 추가)와 5단계(직원)는 다루지 않는다.
- **반목표**(이러면 실패)
  - 없는 보상을 있는 것처럼 보이기: 서버가 주지 않는 콤보·보너스 숫자를 띄우지 않는다. 화면의 금액은 서버 정산과 같은 공식(`tipFor` 등)으로 계산한 값만.
  - 설명이 놀이를 막기: 긴 대사창, 매번 나오는 설명, 손님이 기다리는데 화면을 멈추는 설명 연속. 스토리는 목표만, 대사는 짧게(사용자 기준).
  - CSS 색 박스 연출: 새 UI 조각은 그림으로(CLAUDE.md).

## 3. 설명: 세 겹

### 3-1. 대상 말풍선 (늘)

낮 가게의 `day-prompt` 말풍선과 같은 모양을, 지금 빛나는 대상(`look.glow`) 위에 띄운다. 내용 = 키 + 동사, 할 수 없으면 회색 + 이유.

| 대상 | 할 수 있을 때 | 못 할 때 |
|---|---|---|
| 창구 | E 요리 받기 | 손이 차 있음 / 아직 굽는 중 |
| 손님(주문함) | E 내려놓기 | 다른 요리를 들고 있음 |
| 더러운 자리 | E 닦기 (연타) | — |
| 숯통 | E 숯 넣기 (연타) | — |
| 음료 수레 | E 누르고 있다 떼기 | 손이 차 있음 / 음료 원하는 손님 없음 |

- 모바일은 키 대신 오른쪽 아래 **행동 버튼 글자**가 같은 동사로 바뀐다("행동" → "받기"·"닦기"…).
- 동사·이유는 `shift.canAct`와 같은 판정에서 나온다(새 순수 함수, 테스트).

### 3-2. 뚜껑이 한 줄 안내 (처음 한 번씩)

첫 밤에, 그 상황이 처음 생길 때 화면 위쪽 가운데에 **뚜껑이 얼굴 + 한 줄**(승인된 `art/test/lid/*` 얼굴, 대사창이 아닌 작은 띠)이 4초 뜨고 사라진다. 게임은 멈추지 않는다. 같은 안내는 다시 나오지 않는다.

| 언제 | 뚜껑이(초안, "-껑" 말투) |
|---|---|
| 개점 직후 | "말풍선 요리를 창구에서 받아 갖다주껑!" |
| 첫 요리가 창구에 놓임 | "다 됐껑! 창구로 가서 E껑." |
| 처음 요리를 듦 | "그 요리 시킨 손님한테 가껑." |
| 숯 30% 밑 | "숯 떨어진다껑! 숯통에서 E 연타껑." |
| 첫 음료 요청 | "보리차 손님이껑. 수레에서 꾹 눌렀다 선에서 떼껑." |
| 첫 더러운 자리 | "잔반 치우껑. 안 치우면 다음 손님 못 앉껑." |
| 첫 화난 손님 | "늦으면 화내고 가껑. 평판 깎이껑." |

- **안내를 본 기록**: 진행 데이터가 아니라 화면 편의라 브라우저 저장소에 둔다(제 판단. 기기를 바꾸면 한 번 더 볼 뿐). 낮 대사·프롤로그처럼 세이브에 넣고 싶으면 바꾼다.
- 대사 문구는 후보를 더 뽑아 계획 단계에서 승인받는다(CLAUDE.md 스토리 규칙 — 대사 방향).
- 2일째 이후 처음 하는 상황(예: 3일째 첫 음료)에도 그때 한 번 나온다.

### 3-3. 개점 띠

장사가 시작될 때 낮의 하루 제목 카드(`TitleCard`)와 같은 연출로 "2일째 · 밤 / 영업 시작!" 띠가 1.6초 지나간다(이미 낮 단계 전환에 쓰는 것과 같은 모양, 새 그림 없음). 끝날 때(22시·주문 마감)는 "영업 끝!" 띠.

### 3-4. 황금 숯과 상점은 알게 된 다음에 (사용자 지적 2026-10-20)

사용자: "상점 유도가 뜬금없다. 숯이 뭔지도 모르는데 상점으로 보낸다."

지금 상태:
- 상점 버튼이 **사냥 귀환 화면**과 **업그레이드 창**에 늘 붙어 있다(둘 다 황금 숯과 상관없는 순간).
- 각성에서 황금 숯이 모자라면 버튼이 바로 "상점"이 된다.
- 황금 숯은 장 보스 첫 처치(50개) 말고 게임 안에서 소개되는 순간이 없다. 오른쪽 위 HUD에는 처음부터 "0"으로 떠 있다.
- 밤 가게의 **숯**(숯통, 장사 중 연료)과 유료 재화 **황금 숯**이 여러 곳에서 그냥 "숯"으로 쓰인다("숯 주머니", "숯 {n}", "VIP 하루 숯 받기").

바꾸는 것(제 판단):
1. **알게 되기 전에는 밀지 않는다.** "황금 숯을 안다" = 황금 숯을 한 번이라도 가져 봤거나(첫 보스·구매·VIP) 각성을 한 번이라도 한 세이브. 새로 저장하지 않고 세이브에서 계산한다(`charcoal > 0`, `stars`에 별이 하나라도, `shop.purchases`, 첫 장 보스 처치 = `pages`에 "forest" 중 하나).
   - 그 전: 사냥 귀환·업그레이드 창의 상점 버튼을 없앤다. 각성 카드는 "황금 숯이 모자라요"(누를 수 없음) + 작은 글씨 "장 보스를 처음 잡으면 받아요". 오른쪽 위 HUD의 황금 숯 칸은 숨긴다.
   - 그 뒤: HUD에 황금 숯 칸이 나타나고, 각성에서 모자라면 버튼이 **"황금 숯 구하기"**(→ 상점). 사냥 귀환·업그레이드 창에는 계속 상점 버튼을 두지 않는다(그 순간과 상관없음).
   - 수첩의 "상점" 앱은 그대로 둔다(본인이 골라 여는 곳이라 유도가 아님).
2. **처음 받는 순간을 소개로 만든다.** 장 보스 첫 처치 귀환 화면에 "황금 숯 50을 얻었다!" 줄과 함께 뚜껑이 한 줄(초안: "할미 비법 숯이껑. 장비랑 요리를 각성시키껑."), 수첩의 각성 앱에 처음 한 번 "새로" 표시. 처음이 구매나 VIP라면 같은 한 줄을 그때 보여 준다.
3. **이름을 나눈다.** 유료 재화는 어디서나 **황금 숯**(상품 이름 "황금 숯 주머니"…, 각성 비용 "황금 숯 {n}", "VIP 하루 황금 숯 받기"), 장사 연료는 그냥 **숯**. 황금 숯 그림(승인 대기)이 들어오면 아이콘으로도 구분된다.

이 절은 밤 장사 밖(사냥 귀환·업그레이드·각성·HUD·상점 이름)을 건드린다. 같은 "설명" 작업이라 이 단계에 넣었다(제 판단). 수익 기준(소수 고액 결제자, CLAUDE.md)에는 상점을 일찍·자주 보이는 것보다, 황금 숯이 왜 좋은지 알고 난 뒤 각성에서 막힐 때 한 번 보이는 쪽이 맞다고 봤다.

## 4. 효과 (데이브 반쵸 스시 기준)

이미 있는 `ShiftEvent`마다 화면·소리 반응을 붙인다. 규칙 쪽은 손대지 않는다.

| 순간(이벤트) | 화면 | 소리 |
|---|---|---|
| 손님 주문(`order`) | 말풍선이 통 튀며 나타남 | 짧은 뽁 |
| 인내심 | 말풍선 안 차오르는 색: 초록 → 노랑 → 빨강, 마지막 25%에 흔들림(지금은 빨강 하나) | 마지막 25%에 째깍(한 번) |
| 요리 완성(`cooked`) | 창구 위 김 몇 줄, 반달이 내미는 포즈(있음) | 딩 |
| 요리 받기(`take`) | 손주 들기 포즈(있음) | 접시 달각 |
| **서빙(`served`)** | 손님 기쁨 포즈 + 하트(새 앉은 그림의 happy), 동전 3~5개가 손님 머리에서 튀어 위쪽 골드 칸으로 날아감, 골드 숫자가 굴러 오름, 빠르기 등급 도장 **빠름!/좋아/늦었어**(팁 비율 구간 그대로) | 짤랑 + 동전 들어가는 소리 |
| 화남(`angry`) | 손님 화난 포즈로 나감(있음), 머리 위 붉은 김, 화면 살짝 흔들림(2px, 0.2초), "평판 −2" 붉은 글자 | 툴툴 |
| 음료(`pour`) | 판정 글자를 도장처럼 크게 쿵(PERFECT 금색 + 반짝) | 판정별 다른 소리 |
| 숯(`coal`) | 숯통에서 불티 몇 개, 게이지 출렁 | 사각사각 |
| 숯 없음(`noCoal`) | 반달이 땀 + 숯통 위 빨간 깜빡 | 경고음 한 번 |
| 닦기(`scrub`) | 거품 방울, 끝나면 반짝 + 팁 | 뽀득, 끝에 띵 |
| 다 팔림·마감 | 개점과 같은 띠("다 팔렸다!", "영업 끝!") | 종 |

- **동전·하트·김·불티·거품·반짝·도장 테두리** 같은 작은 그림은 새로 그린다(Codex → 도트 변환 → 승인 → `art/`). 그 전에는 있는 그림(`icon_gold`, 앉은 그림의 하트)으로 대신한다.
- **소리**: 지금 게임에 소리가 없다. Mixkit 효과음(CLAUDE.md)을 위 표만큼 고르고, 음소거 버튼 하나(일시정지 옆)를 둔다. 첫 사용자 조작 전에는 소리를 내지 않는다(브라우저 정책). 고른 소리 목록은 계획 단계에서 들려 주고 승인받는다.
- 움직임은 기존처럼 계단식(`steps()`), 도트가 번지지 않게 정수 배율.

## 5. 정한 것 / 맡기는 것

**정한 것(제 판단, 바꿀 수 있음)**
- 설명은 세 겹(늘 보이는 대상 말풍선 + 처음 한 번 뚜껑이 한 줄 + 개점·마감 띠). 게임을 멈추는 튜토리얼은 없음.
- 안내 기록은 브라우저 저장소.
- 빠르기 등급은 팁 공식의 기존 구간을 그대로 이름 붙인 것(새 보너스 없음).
- 소리는 이번 단계에 넣는다(효과의 절반이 소리라서). 음소거 하나.
- 황금 숯·상점: 알게 되기 전엔 상점 버튼과 HUD 칸을 숨기고, 사냥 귀환·업그레이드 창의 상점 버튼은 없앤다. "안다"는 세이브에서 계산.

**맡기는 것(만드는 사람)**
- 연출 길이·튀는 높이·동전 개수 같은 세부 숫자.
- 효과 레이어 구조: `ShopHud` 위 React 레이어(지금 팝과 같은 방식)로 하되, 순수 판정(말풍선 동사, 안내 발동, 등급)은 `look.ts`처럼 테스트 가능한 함수로 뺀다. 소리는 `src/audio/` 한 곳(플랫폼 연동처럼 모아 둠).
- 2D 대체 가게(`ServiceScene`, WebGL 없을 때)는 대상 말풍선과 개점 띠만 맞춘다(효과 전부는 3D 쪽만).

## 6. 확인 방법

- 단위 테스트: 말풍선 동사·이유, 안내 발동 조건(처음 한 번), 등급 구간이 팁 공식과 일치, "황금 숯을 안다" 판정(새 세이브 = 모름, 첫 보스·구매·VIP·각성 뒤 = 앎).
- 1280×720 화면 확인(headless Chrome, 메모리 `screenshot-1280`): 첫 밤을 처음부터 끝까지 찍어 각 안내·효과가 한 번씩 보이는지, 글자·말풍선이 겹치지 않는지.
- 효과 그림·소리·대사 문구는 넣기 전에 사용자 승인.
